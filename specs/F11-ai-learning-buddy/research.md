# Research: F11 AI Learning Buddy

## Decisions

| Topic | Decision | Rationale |
| --- | --- | --- |
| Scenario | Conversation creation requires exactly one immutable scenario: DAILY_CONVERSATION, VOCABULARY_GRAMMAR or ROLE_PLAY. | Makes teaching intent explicit and prevents a generic unrestricted chatbot. |
| Content | Learner input is plain text of at most 1000 characters. | Bounds privacy, prompt surface and API complexity. |
| Pre-AI safety | Reject unsafe, out-of-scenario or malformed input before message persistence, allowance reservation or provider call. | Ineligible requests must cost nothing and leave no conversation data. |
| Safety classification | Spring Boot permits only Chinese-learning requests matching the selected scenario in Vietnamese or Chinese. It rejects ambiguous input, general chat, prompt injection, PII, sexual content, violence or self-harm, hate and illegal activity. | Keeps the gate testable, prevents pre-gate provider calls and favors safety over ambiguous requests. |
| Rate limit | At most five send attempts per learner in a rolling one-minute window; count accepted and locally rejected input but not an idempotent replay of an existing clientRequestId. | Bounds bursts before provider work while preserving safe retries. |
| Context | At most 10 most recent COMPLETE messages from the same active conversation. | Prevents cross-conversation leakage and controls request size/cost. |
| Handoff | Spring Boot signs the exact UTF-8 newline-delimited uppercase method, path, RFC 3339 timestamp, UUID nonce and lowercase-hex body SHA-256, in that order. The signature is lowercase-hex HMAC-SHA-256 and must match `contracts/f11-hmac-test-vector.json`. Every request declares fixed capability `AI_BUDDY`; responses and typed failures echo the correlation ID. | A normative shared vector prevents Java/TypeScript canonicalization or encoding drift without exposing a deployment secret. |
| Service safety | ai-service independently schema-validates and safety-checks its typed input before provider dispatch and provider output before its response. | Defense in depth is required even though Spring Boot remains the authoritative pre-AI gate. |
| Runtime | One private Node.js + TypeScript container and one Mastra instance; use in-process five-minute nonce replay tracking, with no database, cache, queue or public ingress. | Matches the approved single-container MVP and avoids introducing unapproved infrastructure. |
| Deadline budget | Provider deadline is 22 seconds; Spring Boot private-client deadline is 25 seconds; public terminal response remains capped at 30 seconds with no automatic provider retry. | Preserves time for HMAC validation, output validation, persistence and safe refund/error mapping. |
| Provider runtime | Pin `@ai-sdk/deepseek` beside `@mastra/core` and Zod. Use DeepSeek direct API with required deployment secret `DEEPSEEK_API_KEY`; `DEEPSEEK_MODEL` is required and restricted to `deepseek-v4-flash` or `deepseek-v4-pro`. | DeepSeek documents those V4 identifiers and its direct API endpoint; no browser or Spring Boot process holds the provider key. |
| Provider privacy | AI Buddy uses required `SERVICE_OPERATION`; `AI_MODEL_IMPROVEMENT` is off. Spring Boot/ai-service reject startup or dispatch if DeepSeek key/model or the DPA/no-training/retention/region/attestation policy gate is incomplete, and record only safe provider/model/region audit metadata. | Meets vendor least-privilege, no-training, retention, regional-transfer and audit obligations without persisting chat text in logs or audits. |
| Encryption and erasure | A KMS-wrapped user DEK unwraps a random wrapped DEK for one conversation inside Spring Boot only. Conversation deletion destroys only that conversation envelope before hard deletion. | A global application AES key cannot crypto-erase one chat without affecting other learner data. |
| Output | Required Chinese response plus concise Vietnamese explanation and no more than one suggestion. Output policy V1 rejects missing or oversized fields and prompt/system-instruction disclosure, credentials, PII, sexual content, violence or self-harm, hate, and illegal instructions. | Keeps feedback learning-oriented and renderable under a strict schema without returning unsafe provider output. |
| Failure | An internal pending assistant reply becomes FAILED; allowance reservation is refunded exactly once. | Gives a recoverable user experience and correct F03 accounting. |
| Public response | The send-message operation waits at most 30 seconds and returns a COMPLETE pair or safe terminal error; it does not return PENDING or use polling. | Keeps the MVP interaction simple and aligns the public response with the 30-second success target. |

## Conversation, Key and Audit Rules

Conversations are ACTIVE or DELETED. Each conversation has a random DEK wrapped by the learner's KMS-wrapped user DEK; Spring Boot alone can unwrap it. Delete immediately hides the conversation from standard list and read endpoints, excludes it from context, destroys only its wrapped conversation DEK, appends a content-free deletion attestation, then creates database-backed hard-delete work for rows and enabled search/cache copies. AI chat is retained until learner deletion or 12 months after `last_message_at` (or `created_at` for an empty conversation). The daily backend retention job creates one idempotency-keyed 30-day notice record, retries failed delivery through the configured mail adapter, and processes deletion work without adding a queue or cache. Only an active content-free legal hold created by the privacy/legal workflow may defer deletion; it grants no chat access to that workflow or `ADMIN`. Messages are PENDING, COMPLETE, FAILED or DELETED and have a server-assigned strictly ordered sequence in one conversation.

Only COMPLETE messages from the same conversation can enter the model context. PENDING, FAILED and DELETED messages are excluded. PENDING is internal-only and never exposed by the public API. A user may rename a conversation title but cannot change its scenario.

## Private ai-service Boundary

Spring Boot calls POST /internal/v1/ai-buddy/respond with correlation ID, request ID, fixed `AI_BUDDY` capability, signed replay-protected metadata, scenario, current safe learner content, and at most ten completed contextual messages. ai-service uses Mastra to orchestrate the provider, validates the typed request and safety before dispatch, and validates output schema and safety before returning either a response or a typed internal error containing the correlation ID. The committed contract fixture is the only shared secret/value pair and is test-only; deployment HMAC material is never committed.

ai-service must run as one private container with no public ingress, Mastra Studio exposure, durable memory, database, cache, queue, or logs/traces containing raw learner messages. It returns no quota decision and never calls Spring Boot persistence. It accepts only private-TLS requests carrying `X-Internal-Timestamp`, `X-Internal-Nonce`, `X-Internal-Content-SHA256` and `X-Internal-Signature`; it verifies the exact HMAC canonical string described in the fixture and rejects a missing, invalid, timestamp-outside-the-five-minute-clock-window or replayed value before agent dispatch. An in-process nonce tracker retains replay records for five minutes; horizontal scaling requires a separately approved design.

Before starting traffic, ai-service validates direct DeepSeek configuration: `DEEPSEEK_API_KEY` is a deployment secret and `DEEPSEEK_MODEL` must be `deepseek-v4-flash` or `deepseek-v4-pro`. It accepts no provider/model request field and fails closed unless its DeepSeek DPA, no-training default, encrypted transport, maximum 24-hour vendor retention, deletion/attestation mechanism and transfer region are approved. Spring Boot records dispatch, result/failure and deletion-attestation metadata in `ai_processing_audit_events`; the audit contains no raw chat content, prompt, browser token, HMAC signature, secret or provider body.

Before this boundary, Spring Boot applies the active versioned allow/deny safety and scenario policy. It permits only Chinese-learning requests matching the selected scenario in Vietnamese or Chinese, and locally rejects ambiguous input, general chat, prompt injection, PII, sexual content, violence or self-harm, hate and illegal activity. Rejection is non-persisted and non-billable, not an ai-service request.

## Idempotency and Allowance

The public send request requires clientRequestId and waits at most 30 seconds for the original operation's terminal outcome. A same-fingerprint concurrent repeat joins the original operation and waits only until that operation's immutable initial deadline; it receives the same completed pair or safe terminal error, never PENDING or a fresh 30-second window. A changed request under the same ID returns conflict. Spring Boot reserves F03 allowance with feature AI_BUDDY, calls ai-service outside a long database transaction with a 25-second deadline, validates output, writes the assistant message and settles success; terminal failure refunds the same reservation once. ai-service gives its provider at most 22 seconds and does not retry the provider automatically. Invalid, malformed, or output-policy-rejected provider output maps to `502 PROVIDER_ERROR`; provider or private-service timeout/unavailability maps to `503 SERVICE_UNAVAILABLE`.

Before the safety and allowance gates, Spring Boot limits each learner to five send attempts in a rolling minute. Both accepted and locally rejected input count; an idempotent replay of an existing clientRequestId does not. An excess attempt returns `429` with `Retry-After` and creates no provider call, allowance reservation or message.

## Rejected Alternatives

- Browser calls ai-service or model provider: bypasses authentication, safety and F03.
- Mastra memory retains conversation history: duplicates protected data outside the system of record.
- Sending all conversation history: increases cost and risk and violates the bounded-context decision.
- Persisting invalid/unsafe input for analysis: violates the reject-before-persist policy.
